# Ревью качества кода

## Обзор

Мерило — цена сопровождения: сколько времени следующий читатель потратит на этот
код и в скольких местах ошибётся, когда будет его менять.

Класс или функция понятны без внешнего контекста. Если без него не понять, что
в них происходит, — это дефект самого файла.

## Что судится

Архитектура: SRP, OCP, LSP, ISP, DIP; направление зависимостей и границы слоёв;
временная связанность; границы транзакции и ACID; соразмерность абстракции числу
потребителей. Архитектурный дефект — major, даже когда код работает.

У класса с полем-состоянием назови, какие его публичные методы обязаны идти по
порядку.

Простота: функция принимает то, что использует, и возвращает одно; значение
вычисляется там, где применяется, и передаётся по имени. Класс заводится под
состояние с поведением — класс без состояния это функции, которым приделали
`new`. Мешок (объект, который собирают в одном месте, чтобы разобрать в другом),
фабрика, реестр, сентинел, «умное» значение — каждое требует обоснования; без
него это слой, который читателю надо пройти насквозь. Обёртка, только
передающая вызов дальше, — находка сама по себе.

Остальное качество: обращения за данными внутри цикла, поток управления и
вложенность, контракты между классами, нейминг, копипаста.

## Что не твоё

Статический анализатор проекта (PHPStan, Rector, ESLint и т. п.) уже пишет про
типы, недостижимый код, несуществующие методы, устаревшее API. Форматирование
чинит форматтер. Тесты, докблоки
и бизнес-правила разбирают другие этапы.

Граница: на зафиксированном в baseline легаси анализатор молчит
(`phpstan-baseline.neon`, `eslint-suppressions.json` и аналоги; анализатор,
который смотрит только дифф, легаси вне диффа не видит).
Трогает правка такой код — он снова твой.
